# [California Housing](https://www.kaggle.com/datasets/camnugent/california-housing-prices) — предсказание стоимости домов

Предсказываю медианную стоимость дома в районе (Калифорния, перепись 1990).
Начиналось как учебный проект, но в итоге разобрался, где модель ошибается и почему, — об этом ниже.

**Лучший результат:** HistGradientBoosting — R² 0.857, MAE ≈ $28.9k, MAPE ≈ 15.7%

## Что сделано

1. Почистил данные: выкинул строки, где спален больше, чем комнат всего, и где households = 0 при ненулевом population — это явные ошибки ввода, которые ломают признаки-отношения.
2. Добавил производные признаки (rooms_per_household, bedrooms_per_room и т.д.). Генерация завернута в `FunctionTransformer` внутри пайплайна, чтобы кросс-валидация была нормальной.
3. Прогнал 4 модели от линейно регрессии до бустинга, гиперпараметры искал `RandomizedSearchCV`.
4. Посмотрел не только на R², но и на остатки и permutation importance — там самое интересное.

## Результаты

| Модель | CV R² | Test R² | MAE | RMSE | MAPE |
|---|---|---|---|---|---|
| LinearRegression | 0.524 | 0.654 | $49,606 | $68,786 | 28.5% |
| Ridge | 0.647 | 0.651 | $49,769 | $69,056 | 28.3% |
| RandomForest | 0.814 | 0.823 | $31,611 | $49,168 | 17.2% |
| HistGradientBoosting | **0.842** | **0.857** | **$28,939** | **$44,216** | **15.7%** |

Пара наблюдений:

- Линейные модели упираются в потолок ~0.65. Зависимость явно нелинейная, в основном из-за географии и дохода.
- Ни у одной модели test не проседает относительно CV, так что переобучения нет — разница в пределах шума сплита.
- HistGB стабильно обыгрывает RF на пару процентов — бустинг лучше дожимает хвосты ошибок.

## Где модель ошибается

На графике остатков бросаются в глаза две вещи:

**1. Разброс растет с ценой.** Классическая гетероскедастичность: на дешевых домах ошибка маленькая, на дорогих разлетается до ±200k. Лечится логарифмированием таргета — пока в TODO.

**2. Диагональная «линия» справа и вертикальная стена при $500k на графике предсказаний.** Сначала подумал, что баг в модели, но это артефакт датасета: целевая переменная обрезана сверху (~$500k). Реальная цена дорогих районов неизвестна, известно только «не меньше 500k». Модель предсказывает для таких домов 200–400k, и остаток ложится на идеальную диагональ `500k − pred`. Это ограничение данных, а не модели — чинить на стороне алгоритма нечего.

## Что реально важно (permutation importance)

- **latitude + longitude — суммарно почти половина важности (~48%).** В Калифорнии локация решает всё: побережье и крупные агломерации тянут цены.
- **median_income (~16%)** и **total_rooms (~15%)** — следующие по вкладу.
- Из сгенерированных признаков выстрелил `rooms_per_household` (~5%) — отношения работают.
- `ocean_proximity` после OHE почти не дает вклада. Честно, ожидал большего, но факт: близость к океану и так зашита в координатах, категория дублирует информацию.

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

`main.py` обучает все 4 модели, печатает сводную таблицу, рисует графики и сохраняет лучший пайплайн в `best_model.pkl`. Отдельно `predict.py` умеет предсказывать цену для нового дома по словарю признаков.

## Структура

```
├── data.py            # загрузка и чистка
├── features.py        # генерация признаков (FunctionTransformer)
├── pipelines.py       # ColumnTransformer и сборка пайплайна
├── training.py        # конфиги моделей, поиск параметров, метрики
├── visualization.py   # предсказания / остатки / важность
├── predict.py         # инференс сохраненного пайплайна
└── main.py            # оркестрация
```
